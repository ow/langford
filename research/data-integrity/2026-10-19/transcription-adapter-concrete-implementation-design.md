## Source-side verifier: exact data bindings

A future root-approved store would live under a fixed repository-owned location, not a caller-selected research/private path. Candidate v2 flags denying authority must not be bypassed. Enrollment requires separately approved version/manifest bytes and review membership. Reject path traversal/symlinks, unsupported versions, conflicting duplicate discovery keys, unlisted authority files and changed file bytes. An arbitrary metadata receipt path/hash cannot register data.

For each candidate occurrence, verify:

1. Actual original PDF SHA and original URL/sidecar, source format, native source date and organization provenance. Verify actual ordinary cleaned-text hash separately. Source format or cleanup drift needs review, not text normalization.
2. Actual current raw block/body, offset/order, recomputed existing canonical key and exact own original envelope/outcome. A source receipt is not an instruction to find a different block. Preserve original keys and raw parser inventory; missed prefixes cannot be recovered here.
3. Minimized source witness file/hash and its complete14/26 original introductions, headings, own outcomes, pending-main/amendment/resumption relationships and immediate original adjacency. Check all declared native coordinates against original PDF words and recompute the hash-only full geometry/cleaned/parser evidence transiently. Do not log or republish omitted resident narrative. Non-target bodies are hash/boundary witnesses, not empty or silently removed occurrences.
4. Complete owned target formal excerpt: its separate hash and exact consumed spans within the loaded **full** raw block. Recompute full_raw_block_sha256_hash_only from the actual original block, including omitted context, without confusing it with the shorter public excerpt. The separately projected next heading is not an after-motion narrative tail or source ownership claim.
5. Needed native heading/body/word geometry and actual render dependencies/recipe/page/clip/PNG and sample hashes for each approved glyph locus. Reproduce the v2 capture contract explicitly: native words grouped by original block/line, ordered within line, line bboxes from word unions, document line order as recorded. Native diagnostic indices, cleaned offsets and body-relative offsets remain distinct. Platform/version/binary drift is an exact-evidence hold; no OCR/ML fallback or pixel tolerance is proposed.
6. Every ordered half-open raw-body span: bounds, nonoverlap, exact consumed literal, exact replacement and linked pixel/native witness. Permit the specifically enumerated zero-width comma insertion; missing, repeated or implicit edits hold. Reconstruct the entire accepted output by copying every unchanged run exactly, then require exact accepted full text/hash. Compare corrected stored text by exact full-body output equality, not compact/containment/fuzzy equivalence.

Approved source data may describe a known original introduction not parsed as a completed block (e.g. pending CMHC main after1879). It must remain in the inventory and adjacency model. An unrelated known pending introduction does not globally veto an independently unique target, but a missing, unknown or competing introduction affecting target ownership holds. Original SHA plus reviewed complete inventory is required; do not pretend the existing mover regex discovers every possible hidden prefix.

The verifier returns source transcription evidence only. It must not clear operative_boundary_unknown_held/native_body_not_uniquely_bound_held, assign a legacy row, modify text, or infer voter presence. The separate1739/2910/3847 source approvals remain outside this four-case integration unless root explicitly enrolls another scope and reviews those distinct boundary/geometry rules.

## Complete current claim context and bound comparison

The source receipt has no legacy motion-ID selector. Current canonical metadata is a continuity **claim**, not a trusted authority document. The shared bound verifier re-proves the raw canonical identity and exact source transcription from trusted data, then checks bidirectional ownership against the complete relevant current meeting inventory. Initial canonical assignment to these four legacy rows still requires the separately reviewed finite restoration operation; this adapter cannot bootstrap that assignment from a summary.

Context must include every relevant current row, completed or unresolved, with stable ID, meeting, complete text/result, actor claims and all operative canonical/prior/source-proof claim objects needed to detect competitors. Count-check/paginate; detect a changing inventory rather than accepting a stale selected subset. Build a semantic claim projection that includes ownership-relevant values and excludes avatars, unrelated summaries/FTS, updated_at and unrelated metadata. Full-row CAS remains separate. Preserve and inspect historical operative claims; do not discard them just because they are not top-level canonical_source_motion.

For each candidate raw key, derive both source→row and row→source claim sets and require exactly one qualifying owner under the already reviewed typed identifier/action/actor/item rules. Keep complete raw original-envelope competitors in this decision. Never accept a second row with a copied key. A source block's target-heading mention **after its own outcome** remains context, not an operative claim: preserve the full stored proof and validate exact own-versus-trailing consumed boundaries. The1477→Madrona and1878→TUP mentions are concrete controls.

The new corrected-text branch must hold on missing/incomplete/stale context. Direct calls to inspect_motion/inspect_committee_motion or evaluator/backfill code that previously supplied only one target row must explicitly obtain/pass the same authoritative context; an omitted argument cannot silently grant transcript authority. Existing no-receipt matching should retain its current behavior, avoiding an unrelated blanket hold across historic ballots.

Scope is finite by enrolled **source receipt bytes** and exact discovery keys; no production conditional on1478/1479/1480/1879 is proposed. Only those source occurrences have candidate receipt data, and even they remain inactive until separate enrollment/implementation approval.

## Cache and ordinary ingestion lifecycle: avoid self-invalidating success

This is a required implementation detail, not an optional cache optimization. `source_receipt_current` currently compares validation_inputs exactly; process_meeting captures expected_inputs before final reload and rejects any difference. Adding mutable DB claim state indiscriminately to that object would make the ingester reject its own intended canonical metadata/body writes forever.

The future receipt schema must separate immutable source/runtime validation inputs from current semantic meeting-claim state. Before cache skip, compare both the fresh source inputs and current complete claim fingerprint to the finished receipt. At processing start, freeze authoritative initial claims. Canonical planning and the writer must describe/track their exact intended semantic claim deltas; in this corrected-body scope those are existing-row changes, not new alias-created records.

Before final receipt publication, reload source/runtime facts and complete current claims. Require source facts unchanged and actual claim changes to equal exactly the operation's reviewed/intended persisted deltas, with all unrelated/competing claims unchanged. Then store the freshly verified **post-operation** claim fingerprint for the next skip decision. Never simply omit the claim hash from validation, accept arbitrary post-state, reuse a pre-write hash or normalize away an unexpected delta. If ordinary non-transcription canonical creation is encountered, its separately existing source-driven operations must likewise be explicitly accounted for; no new creation right is introduced by the adapter.

The existing early context, later existing_motions read and final source reload must agree through that lifecycle. A context loaded before another lane changes dates/actors/claims is stale. Future implementation should minimize live-DB rereads through one authoritative context where feasible, but cannot sacrifice completeness or freshness to a cached target-only snapshot. A cache regression must prove successful intended writes can produce a reusable finished receipt and that competing/unrelated claim drift prevents reuse/publication.

## Loaded guard, store discovery and worker lifecycle

Add verifier and shared context helper executable objects to the existing loaded-module guard. official_ballots, canonical_motions, meeting_ballots and committee_ballots are already inspected as imported modules; touched helper code and constants remain included. If process_meeting's lifecycle changes, explicitly bind the loaded `MeetingIngester.process_meeting` code/defaults or factor the shared lifecycle validator into the guarded helper **and also bind the actual orchestration integration**, rather than assuming module-level function inspection sees class methods.

Add the actual loader integration, trusted manifest/review files, all source/receipt/context data actually consumed, all PNG/render metadata and required renderer library/wrapper/version information. Discover and hash the complete sorted actual store file/content inventory; validate it against the manifest. Added/deleted/modified or unknown files must invalidate previous holds/candidates and fail enrollment checks as appropriate. Hashing only files listed in an old cache entry is insufficient.

`source_validation_inputs` must include validated transcription view/inventory hashes and the carefully separated semantic claim state described above. Failed/absent receipts need deterministic status/digests so newly approved receipts invalidate old holds without changing raw source text. Only emit successful transcript proof for the exact receipted occurrence; adding None/diagnostic view keys globally must not silently change unrelated persisted operative proofs.

Restart/redeploy workers after any code/store change. Verify freshly loaded executable digest against the reviewed on-disk/runtime-store/dependency digest before processing; fail on mixed old imported code/new files or stale receipt indexes. A commit or JSON metadata edit alone is not a restart or runtime proof. Candidate future digest fields remain unset until real reviewed implementation and deployment exist.

## Negative controls and finite validation plan

No tests are authored or executed by this design. After separate implementation approval, read test-audit and extend the strongest ordinary owner boundary rather than duplicate helper assertions.

Positive cases: original four PDFs, current raw keys/blocks/offsets/orders unchanged; two exact glyph-corrected and two zero-change full bodies; same successful bound result in canonical existing-row planning/evaluator/merge; subsequent reingest preserves accepted complete stored text. All ordinary date, membership, roster, physical attendance/session, result/tally, policy and existing-choice checks remain independent. Four corrected body matches are not a promise of four completed ballots.

Required source/data negatives: wrong PDF/URL/format/date/organization, raw block/body/key/order/offset drift, unknown or modified manifest/receipt/review files, missing/overlap/out-of-bounds/literal-mismatched/duplicated spans, wrong coordinate system, altered geometry/pixels/render dependencies, missing comma insertion, unlisted output change and shortened1879tail. Recompute full-block hash while using only owned excerpt; reject a trimmed block falsely paired with the full hash.

Required ownership/context negatives:3457/3459 two distinct identical-body envelopes;1615/1616 competing claims; a copied canonical key on a second row; unknown raw prefix/missing relevant introduction; missing CMHC pending main or skipped amendment/resumption relation; treating1477/1878 trailing context as operative ownership; incomplete/paginated/stale target-only context; mutated claim inventory during the ordinary cache/write lifecycle. Unknown/unbound text must stay held even with a valid source receipt.

Required isolation negatives: no receipt can enroll1739/2910/3847 or clear their runtime body holds;3456 dangling `or` is not completed from a heading; no role/action conflation of shared Zoning300 or same actor pair; wrong roster/date/arrival/session/policy still holds despite exact accepted text.

After date-batch independent after-readback and final runtime stability, capture a fresh immutable complete-ballot/source/choice baseline. Run the existing210-test focused suite as the recorded baseline plus separately approved new owner cases; future total will exceed210 as warranted. Preserve failure lineage. Replay the **actual** complete universe, not hardcoded1331/8949 or earlier counts, before and after the adapter using the same source/DB snapshot. Compare full choice rows/IDs, per-person choices/provenance, all non-target motion evidence and raw source/date/roster/result/attendance/occurrence proof. Identify any date-lane proof changes already present in the pre-adapter baseline instead of normalizing them away or attributing them to the adapter. Genuine new ambiguity is reported with existing rows preserved, never weakened to force parity.

Finally replay the four shadow/in-memory proposed canonical text+identity rows through ordinary loader/planner/evaluator/merge under exact reviewed receipts/context without live writes; ensure raw1479/1879 and corrected1478/1480 branches remain distinct and record the real next failing guard. Recheck the separate three-body and duplicate/unknown-prefix controls. Freeze exact runtime/store/renderer/source hashes for independent review before any restoration write planning or live enrollment. This design creates no current final before, applier, rehearsal or mutation authority.
