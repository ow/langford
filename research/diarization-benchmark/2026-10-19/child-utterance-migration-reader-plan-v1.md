## Additive migration shape

Create a separate reviewed migration; do not alter `transcript_segments` columns or insert children into that table. Its verified live columns include bigint `id`, `meeting_id`, nullable `person_id`, `agenda_item_id`, `motion_id`, text attribution fields, double precision `start_time`/`end_time`, `text_content`, boolean `is_verified`, generated `text_search`, and audit timestamps. The identity ledger currently references its ID with `ON DELETE RESTRICT`.

| Proposed relation | Fields and constraints |
| --- | --- |
| `transcript_text_versions` | UUID primary key; bigint parent FK to `transcript_segments(id)` with DELETE RESTRICT; bigint meeting FK; SHA-256 idempotency key unique; expected full parent row JSONB and canonical hash; original artifact/provenance JSONB and hash; state `draft/reviewed/approved/rejected`; immutable creation audit. Composite unique `(id,parent_segment_id)` permits child/pointer FKs that cannot cross parents. |
| `transcript_utterance_candidates` | UUID primary key; UUID version plus bigint parent composite FK; nonnegative ordinal unique within version; finite measured double precision start/end, start < end; exact token index array; exact raw-token text and display text; anonymous run-scoped label; identity state fixed `anonymous_only`. No person-ID or embedding column. Child interval must be within expected parent bounds, validated during admission. |
| `transcript_version_audits` | One row per version; service-only JSONB retaining selected tokens, held lexical units/reasons, context/boundary tokens, native sentence text bindings, original indices, time transforms, temporal evidence and conservation receipt; immutable artifact and validator hashes. Keep raw research private. |
| `transcript_active_representations` | One row per parent segment; optional version UUID composite FK restricted to that same parent; revision bigint and last activation event UUID. No row or null version means legacy parent. Pointer never selects a draft. |
| `transcript_representation_events` | Append-only event UUID, parent, prior/next version UUID, expected pointer revision, reviewer/decision receipt hashes, parent-before hash, activation or rollback timestamp. A rollback is a new event restoring the prior pointer, not a delete or rewritten history. |

Enable RLS and revoke public/anon/authenticated access on **all** five base relations. Only service role can stage private drafts. Public data comes from an explicit safe projection/RPC, never by granting candidate/audit JSON access. Draft storage and publication are separate privileges and transactions. Do not expose raw tokens, before-row JSON, held research text, filenames, person leads or provenance blobs through the public projection.

The proposed projection `effective_transcript_units` returns one branch per parent: the unchanged legacy row if no approved active version, otherwise only that version's admitted children. Include a namespaced text `display_id` (`parent:<bigint>` or `utterance:<uuid>`), numeric `parent_segment_id`, nullable child UUID/version UUID, meeting ID, measured times, public text, `person_id` (null for these children), and explicit `timing_basis`. Avoid reusing the parent numeric ID as each child's rendering key. Keep a separate parent-resolution endpoint for existing citations and history; it is not another countable transcript unit.

## Admission and activation transactions

1. Stage only the two hash-bound draft versions and their children/audit after a new preflight. Lock parents in ID order, require full row equality with the private before snapshots, and repeat unique exact old tuple and recording/raw/cached/token/diarization/config/code hashes. Missing artifacts or changed policy/code means a new reviewed proposal, not a skipped comparison. Staging never changes active pointers.
2. Independently validate selected/context partition and supported/held partition exactly once; raw token text/timing/index preservation; whole-lexical-unit holds; all competing measured voice overlap; native sentence mismatch holds; deterministic child identities; bounds and no cross-parent linkage. Drafts carry `publication_eligible=false` until an independent publication decision. Preserve all unresolved units.
3. Before activation, lock the parent and active pointer, compare expected parent and pointer revision, and recheck `is_verified` and **all** identity-ledger rows. A verified or ledger-bound parent requires a separately reviewed supersession contract; no automatic overwrite or reassignment is allowed. The current two matches have neither protection, but this must be rechecked at write time. Do not modify their existing speaker, person, text, timing, agenda, IDs, or metadata.
4. Root must decide whether partial children with explicit gaps are publishable. The pilot does not authorize omission of 112 held tokens. If approved, render measured gaps as unresolved intervals and offer the preserved original version through history, without attributing held text or filling it into a child's speech. Otherwise keep both versions draft and parent active. The 37 external context tokens remain audit only.
5. Only after all consumers below use the same projection, atomically append an activation event and move one parent pointer with compare-and-swap revision. Concurrency conflict fails the whole transaction. Rollback restores the prior pointer and records an event; children and parent history remain intact. No model or embedding API is part of either operation.

Extend the ingester's early replacement protection (`ingester.py`, before any meeting/attendance/content writes) to detect version FKs as well as existing verified/identity-ledger rows. Direct deletes must fail via RESTRICT. Draft storage cannot accidentally make the existing `replace_transcript` path destructive; require explicit non-destructive reconciliation instead.

## Reader integration and compatibility

Implement one shared server adapter over the effective projection. Do not enable a pointer while any public reader still unions raw parents with children. An integration flag gates the complete reader set; a failure falls back to the complete previous representation, not a mixture of branches.

## Semantic chunk reuse, without word embeddings

`pipeline/ingestion/embed.py` already excludes transcript segment embeddings and builds rich agenda-item discussion embeddings. `services/vectorSearch.ts:searchTranscriptSegments` is deprecated and returns an empty list. Preserve this architecture: no token, word, child or version embedding column and no embedding API calls.

Agenda items 3620 and 5150 already have embeddings and discussion windows overlapping the respective parents. Because both parents have null agenda linkage, these are **window-derived retrieval candidates**, not a proven inherited agenda assignment. Review interval containment and surrounding agenda alignment before recording an explicit navigation-only version-to-chunk link. Reuse the existing chunk's ID/vector as a semantic candidate generator; expand a retrieved chunk through effective units once, without duplicating a vector per child. FTS handles new active text. Mark the existing vector's text basis as legacy/mixed-version where appropriate; do not claim that a reused vector was embedded from the new ASR. Any future chunk text/vector replacement needs separate approval and provenance, not per-word expansion.
